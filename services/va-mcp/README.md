# VA sandbox MCP server (`@vbn/va-mcp`)

An MCP server that wraps two VA Lighthouse **sandbox** APIs so AI tools can use them:

| Tool | API | What it does | Writes? |
|---|---|---|---|
| `find_va_facilities` | VA Facilities v1 | Search by state, city or ZIP, or near a latitude/longitude, filtered by type (health, benefits, Vet Center). Returns name, address, phone, hours, services, website and distance. | No |
| `validate_document` | Benefits Intake v1 | Checks that a PDF from `fixtures/` meets VA file requirements. | No |
| `upload_test_document` | Benefits Intake v1 | Sandbox only. Uploads a fixture PDF for a **fake test veteran** and returns the submission ID. Requires `confirm: true`. | Sandbox only |
| `get_upload_status` | Benefits Intake v1 | Returns a submission's status and what it means. | No |

The Navigator chat uses only `find_va_facilities`. The document tools are for testing with the MCP Inspector.

## Get a sandbox key

1. Go to https://developer.va.gov/explore/api/va-facilities/sandbox-access and https://developer.va.gov/explore/api/benefits-intake/sandbox-access, and request sandbox access. You can request both APIs at once.
2. The key arrives by email. Copy the example file:

```bash
cp services/va-mcp/.env.example services/va-mcp/.env
```

3. Set `VA_API_KEY` in `services/va-mcp/.env`. If your Facilities and Benefits Intake keys are different, set `VA_FACILITIES_API_KEY` and `VA_BENEFITS_INTAKE_API_KEY` instead.

`VA_API_BASE_URL` defaults to `https://sandbox-api.va.gov`. The server **refuses to start** with any other host. The key is sent only in the `apikey` header to the sandbox host, and is never logged, returned in tool results, or sent to the browser.

## Run it

`pnpm dev` at the repo root starts it automatically: the chat service launches this server as a child process over stdio.

On its own (stdio, for MCP clients):

```bash
pnpm --filter @vbn/va-mcp start
```

With the MCP Inspector (opens a browser UI to list and call tools):

```bash
cd services/va-mcp && npx @modelcontextprotocol/inspector node_modules/.bin/tsx src/server.ts
```

In the Inspector, try `find_va_facilities` with `{"state": "MD", "city": "Annapolis", "type": "benefits"}`, then `validate_document` with `{"fixture": "sample-dd214-SAMPLE.pdf"}`. To try an upload, call `upload_test_document` with `{"fixture": "sample-dd214-SAMPLE.pdf", "confirm": true}`, then `get_upload_status` with the returned ID. In the sandbox, status stops at `received`.

To use it from Claude Desktop or Claude Code, register a stdio server whose command is `services/va-mcp/node_modules/.bin/tsx` with argument `src/server.ts` and working directory `services/va-mcp`.

## Tests

```bash
pnpm --filter @vbn/va-mcp test
```

The tests mock HTTP for every tool, and also cover config, the rate limiter, fixture path safety and the MCP server end to end. They never call the VA.

Optional live tests against the sandbox (needs your key):

```bash
pnpm --filter @vbn/va-mcp test:live
```

The live upload test also needs `VA_LIVE_UPLOAD=1`, because it sends the sample PDF to the sandbox.

## Behavior notes

- **Rate limit:** a client-side limiter keeps to 60 requests per minute, and 429 or 5xx responses are retried with backoff (using `Retry-After` when present).
- **Validation:** every tool input and every VA response is validated with Zod. Errors come back in plain language.
- **Logging:** stderr only (stdout carries the MCP protocol), and only tool name, status and duration.
- **Fixtures:** only plain PDF file names inside `fixtures/` are accepted; paths, `..` and symlinks out of the folder are refused. `fixtures/sample-dd214-SAMPLE.pdf` is generated by `pnpm --filter @vbn/va-mcp fixtures` and is watermarked SAMPLE and FAKE.
- **Fake test veteran:** uploads use `Test Sample-Veteran` with file number `999887777`. That's the example from the VA's own docs; numbers starting with 9 aren't valid Social Security numbers.

## Where this follows the VA docs instead of the original prompt

- **No city filter in the Facilities API.** It searches by state, ZIP, latitude/longitude (with radius), bounding box or IDs. City search is done by fetching the state and filtering on each facility's physical address city. For "nearest", pass latitude and longitude.
- **Status path version.** The Benefits Intake "How to Upload" text shows `v2/uploads/{id}` for status, but the published v1 OpenAPI spec lists `GET /uploads/{id}` under v1. This server uses v1, matching the spec.

Sources: [VA Facilities OpenAPI](https://api.va.gov/internal/docs/facilities/v1/openapi.json), [Benefits Intake OpenAPI](https://api.va.gov/internal/docs/benefits-intake/v1/openapi.json), read 2026-11-20.
